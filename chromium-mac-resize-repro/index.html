Mac Chrome resize-recalc regression repro

Bug: on macOS, Chrome ≥ 147.0.7683.0 runs a synchronous style recalc on every resize event instead of coalescing them at the compositor. Does not reproduce on Windows or Linux. Does not reproduce on Chrome ≤ 146.

Bisect range: last known good 1583402 → first known bad 1583431 (both tagged build version 147.0.7683.0). Changelog .

Suspected commit: 8b74eeb7 — [Mac] Use specified deadline 0 when resizing . Removes the browser→renderer back-pressure that previously throttled how fast new viewport sizes reached the renderer, so each Mac resize tick now triggers its own synchronous style recalc.

How to reproduce: drag the native macOS window edge for ~3 seconds. Watch the spinner and the frame-time strip. On affected builds the spinner freezes and bars turn red. On unaffected builds the spinner keeps turning and bars stay green / yellow.

Important: the resize must be triggered by the native window edge or corner — not by dragging a DevTools side-panel divider. DevTools-driven resize bypasses browser_compositor_view_mac.mm and does not exercise the regressed code path, so it appears smooth on both builds.
